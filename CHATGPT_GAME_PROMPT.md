# Reusable ChatGPT game-generation prompt

Create a local Jeopardy game compatible with **jeopardy-game version 1**. I am attaching GAME_FORMAT.md, game-format.schema.json, and examples/text-only.json. Treat the attached JSON Schema as authoritative and follow its exact field names, lengths, integer bounds, six categories with five clues each, and unique category/clue order values.

My theme: [THEME]. Difficulty/audience: [AUDIENCE]. Optional Double Jeopardy: [YES/NO]. Optional Final Jeopardy: [YES/NO]. Daily Doubles: [CHOICE]. Use original factual clues and answers. Choose each category's `attemptPolicy` explicitly: `repeat` for ordinary categories and `one` for true/false or other two-answer categories. Include at least one of each. Keep the game description and media attributions plain text. Do not include executable HTML, URLs for fetching assets, database IDs, session settings, player data, credentials, wagers, or scores. Manual/Automatic activation is selected at game start, not stored in this manifest.

For a text-only game: produce a downloadable UTF-8 .json file with `media: []`, and null `image`/`audio` fields. For a media game: produce a downloadable ZIP with `manifest.json` at the root and actual original or appropriately licensed image/audio files under `media/`. Use supported JPEG/PNG/WebP/MP3/WAV files, within the documented limits. Include their exact relative paths and attribution in `media`, and use the same paths in clues. **A manifest alone or placeholder filenames are not a complete media package.** If you cannot create/include the actual files, give me a valid text-only JSON game instead and explain that limitation. Never silently remove requested media while calling the result a complete media game.

Validate the final file against the attached schema, check order uniqueness and Daily Double limits, verify that every referenced media file is present and every included file is referenced, and report whether it is complete or intentionally a draft. Unsupported versions must not be invented.
